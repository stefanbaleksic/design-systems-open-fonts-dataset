Design System Fonts Dataset

Which typefaces design systems declare, and what the open-licence font families can do

One row per font family: licence, provider, whether it is variable, which OpenType figures, ligatures and Serbian characters it has, and which design systems declare it. Metadata only: no font files are redistributed. Use the filters to narrow the table, the search box to find a name, and click a row for every field.

About this dataset, method and limits

What is measured

  • Licence from the Google Fonts METADATA file or from the repository licence file (text match).
  • Variable: an fvar table is present. Figures: GSUB/GPOS features tnum, lnum, onum, zero; ligatures liga.
  • Serbian: Cyrillic (Ђ Ј Љ Њ Ћ Џ and lower case) and Latin letters with diacritics (Č Ć Š Đ Ž).

Design-system usage

  • 143 design systems with an npm package at the version pinned in the design-systems dataset v33.
  • Text of the package (CSS, JS, TS, JSON) searched for font-family declarations. No code is run.
  • A design system with no brand font in its package is a finding about that package, not proof that the site has no font.

Limits

  • Open families: source-first (original repository), otherwise Google Fonts. One representative file per family.
  • Proprietary faces are recognised by name only; their licences were not read.
  • "Open numbers" is read as oldstyle figures (onum); OpenType has no tag with that name.
  • Figures are read from one file per family, not every style.

Reproduce

  • Run sh scripts/run_all.sh with the clones named in sources.csv.
  • Tests: python3 -m unittest discover -s tests -v.
  • Every file is listed with a SHA-256 in sources.csv and design_system_font_packages.csv.
